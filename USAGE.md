
### Заголовок

- Вкладки переключают основные разделы: «Браузер», «Инспектор», «AI-отчёт».
- Переключатель языка циклически меняет `zh -> en -> ru`.
- Переключатель темы меняет светлую и тёмную тему.
- Кнопки окна управляют сворачиванием, разворачиванием и закрытием приложения.

### Боковая панель

- Список сессий показывает все задачи захвата.
- Кнопка «Новая сессия» создаёт новую задачу.
- Кнопка настроек открывает параметры LLM, proxy, MCP и MITM.

### Строка состояния

Строка состояния показывает активную сессию, количество запросов, количество JS Hook записей, модель LLM и расход токенов после анализа.

## Быстрый старт

### 1. Настройте LLM

1. Откройте настройки.
2. Перейдите в раздел LLM.
3. Выберите provider: OpenAI, Anthropic или совместимый API.
4. Укажите base URL, API key, модель и лимит токенов.
5. Сохраните настройки.

Поддерживаются совместимые OpenAI Chat Completions API сервисы, локальные gateways и Responses API для OpenAI.

### 2. Создайте сессию

1. Нажмите «Новая сессия».
2. Укажите понятное имя.
3. Укажите целевой URL, например `https://example.com`.
4. Нажмите «Создать».

### 3. Захватите трафик

1. Откройте целевой сайт во встроенном браузере.
2. Нажмите «Начать» в панели браузера.
3. Выполните нужные действия: вход, отправка формы, чат, оплата, загрузка данных.
4. Нажмите «Остановить».

### 4. Запустите анализ

1. Перейдите в «Инспектор».
2. Выберите режим анализа.
3. При необходимости выделите конкретные запросы.
4. Нажмите «Анализ».
5. Откройте «AI-отчёт» и задавайте уточняющие вопросы.

## Сессии

Сессия хранит:

- HTTP-запросы и ответы;
- JS Hook записи;
- снимки Cookie, localStorage и sessionStorage;
- пользовательские события;
- AI-отчёты и историю follow-up чата.

Статусы сессии:

| Статус | Значение |
| --- | --- |
| Выполняется | Захват активен |
| Приостановлена | Захват временно остановлен |
| Остановлена | Захват завершён, можно анализировать |

Удаление сессии удаляет связанные данные. Если AI-чат ещё отвечает, удаление защищено до завершения ответа.

## Браузер

### Навигация

- Адресная строка принимает URL и запускает переход по Enter.
- Кнопки назад, вперёд и обновить управляют текущей вкладкой.
- DevTools можно открыть из панели браузера.

### Вкладки

- Кнопка `+` создаёт новую вкладку.
- Всплывающие окна OAuth открываются как внутренние вкладки.
- Последняя вкладка защищена от случайного уничтожения.

### Управление захватом

- «Начать» запускает запись запросов.
- «Пауза» временно приостанавливает запись.
- «Продолжить» возобновляет запись.
- «Остановить» завершает захват.

## Инспектор

### Запросы

Таблица запросов показывает:

| Колонка | Описание |
| --- | --- |
| `#` | Порядковый номер запроса |
| Method | HTTP-метод |
| Domain | Домен запроса |
| Path | Путь и query string |
| Status | HTTP-статус |
| Time | Время выполнения |
| Source | Источник: CDP или Proxy |

Доступны поиск по URL, сортировка, фильтры по колонкам и экспорт запросов в JSON.

### Детали запроса

Панель деталей содержит:

- заголовки запроса;
- тело запроса;
- заголовки ответа;
- тело ответа;
- связанные JS Hook записи.

JSON форматируется автоматически, текстовые ответы подсвечиваются как код.

### JS Hooks

JS Hook записи помогают понять фронтенд-логику:

- fetch и XHR;
- crypto.subtle;
- CryptoJS;
- операции подписи и шифрования;
- запись Cookie через `document.cookie`.

### Хранилища

Раздел хранилищ показывает снимки и diff:

- Cookies;
- localStorage;
- sessionStorage;
- добавленные, изменённые и удалённые ключи.

## AI-отчёты

### Режимы анализа

| Режим | Что делает |
| --- | --- |
| Автоопределение | Определяет сценарий и формирует общий отчёт |
| Реверс API-протокола | Описывает endpoints, параметры, ответы и аутентификацию |
| Аудит безопасности | Ищет утечки, слабую аутентификацию, CSRF/XSS и проблемы доступа |
| Анализ производительности | Разбирает тайминги, дубли и кэширование |
| Реверс JS-шифрования | Восстанавливает алгоритмы, ключи, подписи и код воспроизведения |

### Двухэтапный анализ

Если запросов много, сначала запускается предварительная фильтрация. AI выбирает релевантные запросы, а затем выполняет глубокий анализ. Если данных не хватает, модель может вызвать встроенный инструмент `get_request_detail` и посмотреть полный контент любого запроса.

### Follow-up чат

После отчёта можно задавать уточняющие вопросы. Чат получает:

- предыдущий отчёт;
- краткую сводку захваченных запросов;
- доступ к `get_request_detail`;
- выбранную локаль интерфейса.

При русской локали системные подсказки, progress-сообщения и ответы follow-up чата формируются на русском.

### Экспорт

Отчёт и follow-up историю можно экспортировать в Markdown.

## MITM-прокси

MITM-прокси нужен для внешних приложений, терминала, скриптов и мобильных устройств.

### Включение

1. Откройте настройки.
2. Перейдите в «MITM-прокси».
3. Включите прокси.
4. Установите CA-сертификат.
5. Для системного трафика включите «Системный прокси» или настройте приложение вручную.

### Примеры

```bash
curl -x http://127.0.0.1:8888 https://api.example.com/data

https_proxy=http://127.0.0.1:8888 wget https://api.example.com/data

HTTP_PROXY=http://127.0.0.1:8888 HTTPS_PROXY=http://127.0.0.1:8888 node app.js
```

```python
import requests

proxies = {
    "http": "http://127.0.0.1:8888",
    "https": "http://127.0.0.1:8888",
}

response = requests.get("https://api.example.com/data", proxies=proxies)
```

### Мобильное устройство

1. Подключите телефон и компьютер к одной сети.
2. Включите MITM-прокси.
3. На телефоне настройте Wi-Fi HTTP proxy: IP компьютера и порт `8888`.
4. Установите и доверьте CA-сертификату.
5. Создайте сессию и запустите захват.

### Ограничения

- Certificate pinning может блокировать расшифровку HTTPS.
- WebSocket-трафик туннелируется и не расшифровывается.
- Бинарные тела пропускаются.
- Размер одного body ограничен настройками приложения.

## Настройки

### Общие

- Язык интерфейса.
- Тема оформления.
- Проверка обновлений.
- Очистка логов ошибок.

### LLM

- Provider.
- API type.
- Base URL.
- API key.
- Model.
- Max tokens.

### Prompt templates

Встроенные шаблоны доступны на русском, английском и китайском. Пользовательские шаблоны можно создавать, редактировать, удалять и сбрасывать. Если пользователь изменил встроенный шаблон, сохранённые значения считаются пользовательскими и не перезаписываются локализацией.

### MCP Client

Подключает внешние MCP Server через stdio или StreamableHTTP. Подключённые tools становятся доступны AI-анализу.

### MCP Server

Открывает возможности Anything Analyzer как MCP tools. Для AI tools можно передать `locale: "ru"`, чтобы отчёты и follow-up ответы были русскими.

### Proxy

Настраивает исходящий HTTP, HTTPS или SOCKS5 proxy для самого приложения.

### MITM-прокси

Управляет HTTPS-прокси, портом, системным proxy, CA-сертификатом, экспортом и регенерацией сертификата.

## Частые проблемы

### LLM provider not configured

Откройте настройки LLM и сохраните provider, ключ, base URL и модель.

### MITM-прокси не видит HTTPS

Проверьте:

1. CA-сертификат установлен и доверен.
2. Внешнее приложение действительно использует proxy `127.0.0.1:8888`.
3. Сайт или приложение не использует certificate pinning.
4. Захват в текущей сессии запущен.

### AI-анализ пропускает важный запрос

Выделите нужные запросы вручную и запустите анализ по выбранному диапазону. Также можно задать уточнение в follow-up чате и попросить модель вызвать `get_request_detail` по номеру запроса.

### Русский текст не отображается

Проверьте, что выбран язык `Ru` в заголовке приложения. Если строка остаётся на другом языке, добавьте ключ в `src/renderer/i18n/ru.ts` и проверьте правила в `docs/ru-localization.md`.
