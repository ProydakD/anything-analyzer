# Проектирование выбора цели анализа

**Дата:** 2026-04-13
**Статус:** утверждено
**Проект:** Anything Analyzer

## Цель

Добавить возможность выбрать предопределённый сценарий анализа или ввести собственную инструкцию перед запуском AI-анализа. До этого `PromptBuilder` всегда использовал один фиксированный системный prompt и один набор требований.

## Предопределённые сценарии

| ID | Русская метка | Назначение |
| --- | --- | --- |
| `auto` | Автоопределение | AI сам определяет сценарий и формирует общий отчёт |
| `reverse-api` | Реверс API-протокола | Endpoints, схемы запросов и ответов, аутентификация, модель данных, код воспроизведения |
| `security-audit` | Аудит безопасности | Уязвимости аутентификации, утечки данных, CSRF/XSS, небезопасные заголовки |
| `performance` | Анализ производительности | Тайминги, лишние запросы, порядок загрузки ресурсов, кэширование |
| `custom` | Своя инструкция | Пользователь вводит произвольный фокус анализа |

## Поток данных

Параметр `purpose?: string` проходит по цепочке:

```text
ControlBar -> App.handleAnalyze
  -> useCapture.startAnalysis
    -> electronAPI.startAnalysis
      -> IPC ai:analyze
        -> AiAnalyzer.analyze
          -> PromptBuilder.build
```

Если `purpose` пустой или равен `auto`, используется общий анализ. Для известных значений подставляются специализированные требования. Для произвольного текста пользовательский фокус добавляется к базовому анализу.

## Изменения PromptBuilder

`PromptBuilder.build()` принимает `purpose` и выбирает требования:

- `auto`: сценарий, цепочка действий, API, аутентификация, streaming, storage, зависимости, воспроизведение;
- `reverse-api`: endpoints, параметры, ответы, auth flow, модель данных, Python requests;
- `security-audit`: authentication, sensitive data, CSRF/XSS, headers, access control;
- `performance`: request timing, duplicates, resource loading, cache strategy;
- произвольный текст: пользовательский фокус плюс базовый анализ.

## UI

В панели анализа добавляется selector сценария:

- список предопределённых режимов;
- вариант «Своя инструкция»;
- поле ввода для пользовательского фокуса;
- передача выбранного значения в `onAnalyze(purpose)`.

## IPC и preload

`startAnalysis` получает необязательный `purpose`:

```typescript
startAnalysis: (
  sessionId: string,
  purpose?: string,
) => Promise<AnalysisReport>;
```

IPC handler `ai:analyze` прокидывает параметр в `AiAnalyzer`.

## Проверки

- Unit-тесты `PromptBuilder` для всех режимов.
- Проверка совместимости `auto` с прежним поведением.
- Проверка пользовательского текста.
- Smoke test UI: выбор режима, запуск анализа, отчёт.

## Риски

- Слишком узкий сценарий может пропустить важные запросы.
- Пользовательский prompt не должен ломать базовую структуру отчёта.
- UI должен сохранять понятный fallback при пустом выборе.
